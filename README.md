# 微信小程序视频/图片下载器（WechatMiniProgramScrab）

检测 Windows 上正在运行的**微信小程序窗口**，把这些小程序里的**视频（含 m3u8）和图片（JPG/PNG）**
解析出来并下载。支持**批量下载全部**、**一键下载全部 m3u8** 或**勾选单条下载**，
带完整 GUI、命令行模式和完善日志。

> 只处理你自己电脑上、你自己有权限访问的内容。请遵守微信/小程序平台的用户协议与版权规定，
> 不要用它抓取或传播你没有权利使用的内容。

---

## 1. 它解决什么问题

微信 PC 端的小程序不是普通窗口：它跑在独立的 `WeChatAppEx.exe`（WMPF / Chromium）进程里，
视频地址往往带签名、会过期，也不提供下载按钮。本工具用几条互相独立的通道把它挖出来：

| 通道 | 原理 | 可靠性 | 需要什么 | 默认 |
|---|---|---|---|---|
| **本地缓存文件** | 小程序播放/下载过的视频会落在 `applet\local\<appid>\temp\*.mp4`，直接复制 | ★★★★★ 拿到的是完整原始文件 | 视频被播放/预加载过 | **关** |
| **内存扫描** | 读 `WeChatAppEx.exe` 进程内存，正则捞出 CDN 直链（实测能捞到 `mpvideo.qpic.cn` / `wxsmw.wxs.qq.com` 等） | ★★★★☆ 拿到的是签名直链，可能已过期 | 视频**正在播放**时扫最准 | **关** |
| **Chromium 缓存 URL** | 从 `web\profiles\*\Cache\Cache_Data` 里回收历史 URL | ★★☆☆☆ 大多是旧链接 | 无 | **开** |
| **CDP 调试端口** | 有 DevTools 端口时直接读页面 `<video>` 与网络请求 | ★★★★★ | 需要 Frida/WMPFDebugger 打开调试端口 | **关** |
| **图片（JPG/PNG）** | 复用上面启用的来源通道，额外收集 jpg/jpeg/png（含小程序 local 目录里的图片文件） | ★★★☆☆ 会混入图标/头像/广告图 | 至少一个来源通道 | **关** |

**为什么默认关掉这几条？**
- 「内存扫描」和「本地缓存文件」在「鹅打卡」这类小程序里捞到的几乎全是**广告**；
- 「图片」实测一次探测能从缓存里翻出 **800+ 张**图标/头像/广告图，会把列表淹掉；
- 「CDP」微信默认根本不开放调试端口。

所以默认只留最轻的「缓存 URL」。需要更全的时候在界面勾上对应通道，或改 `config.json`
（`channels` 段就是“默认是否开启”）。

**录制功能已删除**（有专门录屏软件就不必让本程序兜底），所以现在只有“解析—下载”。

## 2. 环境要求

- Windows 10 / 11（x64）
- Python 3.9+（本机验证：3.11.7，64 位）
- 微信 PC 端已登录，且在微信里**打开过一个小程序**
- 可选：`ffmpeg` + `ffprobe`
  （HLS 合并、下载后完整性体检都靠它；没有 ffmpeg 也能下直链 mp4 和图片，但 m3u8 下不了）

### 安装依赖

```bat
pip install -r requirements.txt
```

`tkinter` 是 Python 自带；`websocket-client` 只有 CDP 通道需要；`Pillow` 只用于窗口截图预览。

## 3. 快速开始

### 图形界面（推荐）

```bat
python run.py
```

或者双击 `run.bat`。

界面分四块：

1. **① 小程序窗口** —— 自动检测；有多个时手动选一个（双击某行即选中）。
   「预览窗口截图」可以直接看到选中窗口的画面，确认没选错。
2. **② 探测选项** —— 左侧五个通道复选框；**右侧同一行**放「内存预算 / 下载并发 / CDP 端口」；
   下面是输出目录、**「开始探测 / 取消」合并按钮**（探测中自动变成「取消」，点一下即取消）
   和它右边的进度条。
3. **③ 列表** —— 点最左边的 `✓` 列切换单条选择；
   「全选」是一个**勾选框**（勾上=全选，再点=全不选）；
   「下载选中 / 下载全部 / 全部m3u8」三个下载入口；右上角可按「视频 / 图片」筛选，
   双击任意行看该条的完整 URL / 路径 / 判定依据 / 下载告警。
4. **④ 运行日志** —— 实时显示底层细节（进程内存区块、HTTP 头、ffmpeg 输出……），
   可切换级别、清空、保存副本、定位日志文件。

### 命令行（批量 / 自动化 / 排查）

```bat
python run.py --list-windows                 :: 只列窗口，不开界面
python run.py --probe                        :: 用 config.json 里的默认通道探测
python run.py --probe --channels cache,mem   :: 只走指定通道（mem,cache,cacheurl,cdp,images）
python run.py --probe --download all --out D:\videos
python run.py --probe --download m3u8        :: 只下探测到的全部 m3u8
python run.py --probe --download 1,3         :: 只下第 1、3 条
python run.py --selftest                     :: 全链路自检（不需要微信在播视频）
```

`--hwnd 0x28d14e4` / `--pid 16872` 可以精确指定目标窗口（句柄从 `--list-windows` 里取）。

## 4. 配置文件 `config.json`

程序根目录的 `config.json` 保存**所有开关和数值的默认值**，改完存盘后重启程序生效
（界面里临时改的只影响当次运行，不会写回文件）。首次启动会自动生成，内容如下：

```json
{
  "channels": {
    "memory": false,        // 内存扫描
    "cache_files": false,   // 本地缓存文件
    "cache_urls": true,     // Chromium 缓存 URL
    "cdp": false,           // CDP 调试端口
    "images": false         // 图片（JPG/PNG）；要收图片就改成 true
  },
  "numbers": {
    "scan_budget_mb": 900,      // 内存扫描总预算（MB）
    "concurrency": 3,           // 下载并发
    "cdp_port": "",             // 手动指定 CDP 端口，如 "9222"
    "cache_url_budget_mb": 512, // 缓存 URL 扫描总读取上限
    "cache_url_file_mb": 64,    // 单个缓存文件最大读取
    "min_local_mb": 0.08,       // 本地缓存文件小于该体积忽略
    "min_image_kb": 24,         // 图片小于该体积忽略（过滤图标）
    "http_timeout": 30.0,
    "http_retries": 3,
    "local_wait_seconds": 8.0,  // 复制本地缓存前最多等它“写完”多少秒
    "hls_expand_masters": true, // m3u8 主清单自动展开成所有清晰度
    "native_hls": true          // 用内置分片下载器下 HLS
  },
  "gui": {
    "out_dir": "",              // 留空 = 程序目录下的 downloads/
    "log_level": "DEBUG",
    "autoscroll": true,
    "show_all_windows": false
  }
}
```

界面里也有入口：「文件 → 打开配置文件 config.json」「工具 → 重新加载 config.json」。

## 5. 使用流程（成功率最高的顺序）

1. 在微信里打开目标小程序，**点开视频播放 3~5 秒**（让 URL 进内存、让缓存落盘）。
2. 点「重新检测窗口」，确认选中的是目标小程序。
3. 点「开始探测」。默认只跑「缓存 URL」，几秒钟；勾上更多通道会更全、也更慢。
4. 列表里出现条目后：
   - 绿色「本地缓存文件」= 完整原始文件，直接复制，最稳；
   - 「直链视频 / HLS 播放列表」= 从内存或缓存里解析到的地址，单独或批量下载；
   - 「图片」= jpg/png，单独或批量下载。
5. 一条都没有？依次尝试：
   - 只勾「本地缓存文件」再探测（有些小程序播放时不产生直链，但会落盘）；
   - 勾上「内存扫描」，内存预算调大（默认 900MB），并确认视频正在播放；
   - 视频是加密流/DRM 时程序拿不到，只能另想办法（录屏等）。

## 6. m3u8（HLS）与“下载不完整”的处理

### 6.1 自动获取所有 m3u8

* 探测时会自动识别 `.m3u8`（包括路径里没扩展名、签名在查询参数里的写法）；
* 遇到 **主清单（master playlist）** 会**自动展开**成每个清晰度一条，条目名带分辨率/码率；
  展开是**并行 + 单次尝试 + 6 秒超时**（最多 12 个清单），所以不会明显拖慢探测；
* 「**全部m3u8**」按钮把列表里所有 m3u8 一次性下载；命令行用 `--download m3u8`。

### 6.2 为什么以前会“时长对但前半段没声音、画面不动”

这类文件的 moov（时长/索引）是完整的，缺的是 mdat 里的一部分数据。常见原因：
1. 直接把 m3u8 交给 ffmpeg —— 某个分片请求失败时 ffmpeg 可能**跳过该分片继续写文件**；
2. 复制**还在写入**的小程序缓存文件（拿到的是半成品快照）；
3. 断点续传时服务器返回的 `Content-Range` 起点对不上，文件中间出现空洞。

### 6.3 这一版的改进（都是为“下得全一点”）

| 改动 | 说明 |
|---|---|
| **内置 HLS 分片下载器** | 逐片下载 + 每片校验 `Content-Length` + 失败重试；支持 `EXT-X-KEY:AES-128`、`EXT-X-MAP`(fMP4)、`EXT-X-BYTERANGE`、`EXT-X-DISCONTINUITY`；全部到位后才让 ffmpeg 做**本地**拼接，网络因素彻底排除 |
| **时长核对** | 下完用 ffprobe 对比“清单声明总时长”和“成品时长”，差异超过 3%（或 2 秒）就在日志和状态里告警 |
| **本地缓存等待写完** | 复制前先等文件大小稳定（`local_wait_seconds`），复制到 `.part` 再改名，复制后再对比源文件有没有变大 |
| **零块检测** | 成品前 8MB 里“全零块”占比 >15% 就说明前段没数据 —— 直接命中上面那个症状，状态显示为「已完成⚠」 |
| **解码体检** | 用 ffmpeg 解码成品开头 15 秒，统计报错行数；有错就告警（详情面板里能看到原因） |
| **Referer 兜底** | 403 时按微信文档的 `referrer-policy`（`https://servicewechat.com/{appid}/0/page-frame.html`）换 Referer 重试 |
| **断点续传更严** | 写完后核对总长度，不足就续传重试；`.part` 不会当成成品 |

如果某条仍然只有“已完成⚠”，说明素材本身就是不完整的（小程序还在缓存中、或 CDN 给了残缺数据）。
**等视频完整播放一遍再重新探测**，或者改用直链而不是本地缓存快照，通常就能拿到完整的。

## 7. 常见问题

**Q：不手动开始播放，是不是就拿不到缓存 URL？**
- **历史缓存 URL 能拿到**：Chromium 缓存里存着上次访问过的地址，「缓存 URL」通道不播放也能回收（可能已过期）。
- **当前这次会话的新地址基本要靠“发请求”**：浏览器/小程序播放器只有在真正请求媒体时才会把
  m3u8/分片地址写进内存与网络栈。视频组件 `autoplay` 默认是 false，所以通常要你点一下播放；
  但不少小程序会**预加载**首段（`wx.preloadVideo`、`initial-time` 等），这种不点播放也可能被扫到。
- 想把“不播放也能拿”做到最好：勾上「内存扫描」+「缓存 URL」，并**先在小程序里划过/打开过目标页面**
  （触发预加载）；有 DevTools 调试端口时用 CDP 通道最干净。

**Q：检测不到小程序窗口？**
- 确认微信主程序（`Weixin.exe`）已登录；小程序窗口不能是“已关闭/最小化到托盘”。
- 工具会主动**排除 QQ** 的内置小程序运行时（QQ NT 里也有一个同名的 `WeChatAppEx.exe`）。
- 想看全部 Chromium 窗口（含浏览器、QQ），勾选「显示全部 Chromium 窗口」。

**Q：探测到 0 条？**
- 视频还没开始播放，内存里还没有地址；先播放几秒。
- 只勾「本地缓存文件」试一次。
- 日志里会写清楚每条通道的结果（扫了多少 MB、命中多少 URL、为什么被过滤）。

**Q：下载 403 / 无权限？**
- 微信 CDN 的直链带签名（`dis_t` 时间戳），**会过期**。列表里已过期的条目不会展示；
  如果下载时才过期，重新播放视频后再探测一次即可。
- 有些地址绑定 Referer / 登录态，工具已带 `Referer: https://servicewechat.com/` 和微信 UA，
  403 时还会按 appid 换 `page-frame.html` 形式的 Referer 重试。

**Q：下载的 mp4 打不开？**
- 日志里会打印文件头十六进制和 ffprobe 信息。若文件头是 `<!doctype html`，
  说明服务器返回的是错误页（通常是签名过期）。
- 检查 `logs\` 目录最近一个日志文件，里面有完整的请求/响应头。

**Q：为什么第一次探测要几十秒？**
- 默认只跑「缓存 URL」，本机实测约 **3~4 秒**。
- 勾上「内存扫描」要多读几百 MB 进程内存（900MB 预算约 4 秒）；「本地缓存文件」要遍历小程序
  local 目录；全通道本机实测约 **11 秒**（300MB 内存预算）。
- 可以在界面调小「内存预算」，或只勾需要的通道。

**Q：图片通道默认为什么关？图片太多、全是广告图怎么办？**
- 实测鹅打卡一次探测能从 Chromium 缓存里翻出 **896 张** jpg/png（图标、头像、广告图），
  列表会被淹掉，所以默认关。
- 要看图片：在 ② 里勾「图片（JPG/PNG）」，再用 ③ 右上角的筛选切到「图片」。
- 嫌小图/图标多：把 `config.json` 的 `numbers.min_image_kb` 调大
  （默认 24KB 以下的图片下载后会被跳过并删除）。

## 8. 日志与排错

- 日志文件：`logs\wxs_<日期>_<时间>_<pid>.log`（UTF-8，DEBUG 级，8MB 轮转，保留 6 份）
- 启动时会打印环境快照：Python、系统版本、是否管理员、DPI、微信数据目录、ffmpeg 路径、配置摘要……
- 每条关键操作都有耗时；Win32 失败会带错误码和 `FormatMessage` 文本；
  HTTP 会打印状态码、响应头、Content-Type；ffmpeg 的输出逐行进日志。
- 下载完成后的“体检结论”（文件头/零块比例/时长/解码报错）也会写进日志。
- 遇到问题，**先把最近一份日志发给维护者**，信息比截图全得多。

## 10. 已知限制

- 微信小程序默认**不开放** DevTools 调试端口，因此 CDP 通道一般是“不可用”（会明确提示）。
- 内存里的签名链接有时效，过期后必须重新播放再扫。
- **录制功能已删除**；加密流 / DRM / 纯 canvas 渲染的内容本工具拿不到。
- 小程序用的 HLS 如果带 `SAMPLE-AES`（DRM），内置下载器只能下到密文，会明确失败。
- 只做了 Windows；微信 3.x 的目录结构已兼容，但本机只在微信 4.x 上实测过。
